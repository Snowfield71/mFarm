# 牧场建筑设计 Skill

> 目的：为牧场建筑外观、室内场景、交互层与玩法入口提供同一套可执行的视觉和结构约定。它补充 `art-design.md` 的通用美术规则，不替代植物素材规范。

## 1. 项目风格基准

- 延续项目现有的精致二维手绘农场风格：温暖、柔和、童趣；暖棕描边、左上柔光、简洁两级明暗、短而轻的接地阴影。
- 建筑同组使用一致的三分之四前视角、地面基线、视觉占比、描边粗细、圆角和环境层。不同建筑可使用不同材质与配色，但不得出现写实渲染、3D 塑料感、繁杂木纹或互相矛盾的透视。
- “统一”指共享视觉语法，不是复制同一栋房子：每栋建筑保留清晰的功能轮廓和专属结构。

### 1.1 牧场外观固定镜头（硬性验收）

本节适用于所有牧场建筑的新绘、重绘和替换。**任一建筑未通过朝向验收，整张图集不得接入项目。**

1. **锁定镜头**：必须采用**正交投影**。从面向建筑正面的机位绕向建筑右侧 **26°**，向下俯视 **18°**，滚转 **0°**。画面始终露出左侧正面和向右后退的侧面；禁止镜像、反向透视或为个别建筑另设镜头。
2. **抽测直边**：在最终 **256 × 256** 分图上，以屏幕水平线为 0°，从左往右标注代表性结构的两端。正面水平边（门槛、栏杆、滑轨）目标为向右下 **8.6°**，验收范围 **0.6°–16.6°**；右侧纵深水平边（侧檐、墙脚、基座）目标为向右上 **32.3°**，验收范围 **22.3°–42.3°**。可辨的两条轴分别抽测，竖柱保持竖直。弧线切线、倾斜坡道的纵边及装饰线不能作为水平轴样本；画反、超差，或门窗与房体透视互相矛盾，均须重画后复验。
3. **圆形建筑同样必验**：鸡舍、蜂窝、温室和水井保留圆身。可辨的门槛、横梁、卷轴等直边按同一范围抽测；没有可测直边的方向，须用入口、侧窗或玻璃骨架与可见底座一起和已通过的样例同屏对照，并记录判断依据。朝向读不出来即不通过，不得为了测角加假侧墙。
4. **统一显示尺度**：同组使用 **256 × 256 RGBA** 透明格，主体 alpha 包围盒水平居中，建议宽 **210–224 px**，右开区间的 alpha 下边界对齐 **y=242**。只做等比缩放与平移，保留不同建筑本身的高矮。
5. **发布前复核**：逐格保留测角标注或圆形体块的判读记录，检查原尺寸和游戏的 **72 px** 同屏效果。镜头参数与建筑图集清单中的 `camera` 一致；这些角度用于绘制和验收，不是运行时旋转参数，不改变图集裁切坐标。

## 2. 屋顶与房体统一规则

- 牧场建筑的基础屋顶语言统一为**连续、饱满的圆弧 / 半圆拱形轮廓**：左右弧线平顺，弧顶连续，檐口落点一致；避免一个屋顶像圆滑拱顶、另一个像分段半球或一簇独立圆包。
- 外轮廓可以按建筑功能调整高宽比，但所有圆弧顶必须遵循同一曲率家族、檐口厚度和描边权重。屋面分片沿弧面透视收敛，不能与房体透视方向冲突。
- 房体墙面、屋顶、门窗和基座须有清楚的前后关系；正面入口应可读，建筑落地，底部环境层不得遮盖入口或交互主体。
- 功能差异通过材料、开口、装饰和设备表达，而非改用完全不同的视角或轮廓语法。温室可保留透明玻璃弧顶；仓库等已定义的专属屋面不强行改成住宅屋顶，但须沿用同一描边、光照、透视、基线和圆角语言。

## 3. 外观为室内与玩法的唯一视觉母版

每栋可进入建筑先建立一张“外观—室内—玩法”对应表，再绘制或调整室内场景。室内必须让玩家一眼认出它来自对应外观：

| 外观识别项 | 室内必须延续 | 玩法 / 交互必须对应 |
| --- | --- | --- |
| 屋顶轮廓、屋面材料与主色 | 可见的屋顶内侧弧线、梁架或对应材质；弧度、色相与外观一致 | 不新增与建筑用途冲突的生产功能 |
| 墙体、门窗、入口位置 | 墙体色与门窗样式相同；空间纵深方向与入口一致 | 可点击对象布置在空间中对应的功能区 |
| 花箱、栅栏、蜂巢窗、玻璃骨架等标志结构 | 以相同形状、颜色或材料再次出现，不能被另一类建筑的装饰替代 | 交互槽、状态提示和操作入口贴合实际设施 |
| 基座、地面和建筑尺度 | 地板、通道、栏位与入口尺度自然衔接 | 点击热区覆盖可见设施，状态对象与视觉槽位一一对应 |

室内背景只绘制固定结构和空置基座；动物、作物、产品、生产进度等动态状态由运行时层渲染，避免图片与玩法状态重复或不一致。室内层级按“远景墙体 / 屋顶内侧 → 固定设施 → 动态生产对象 → 操作控件”组织；前景装饰不得遮挡标题区、对象主体或触控目标。

## 3.1 场景布局与素材深度层

借鉴经典 2D 横版场景“分层构景、前后遮挡、主体落点清晰”的方法，不复刻任何现成地图或素材。室外农场可使用克制的多层视差；室内是固定镜头，使用深度层与遮挡关系，不做无意义的视差动画。

牧场场景按以下渲染顺序拆分。图层必须在文件与节点树中有稳定、可读的名字：

1. `FarBackground`：天空、远丘、远树或室内最深处墙面；低对比，不承载点击。
2. `ArchitectureBack`：建筑后墙、屋顶内侧、窗户、梁架、固定装饰；与外观结构/材质一致。
3. `FunctionalSet`：栏位、花床、蜂巢格、温室种植架、地板通道等固定设施；设施空位和运行时槽位一一对齐。
4. `ActorsAndState`：动物、作物、产品、进度与选中状态；按接地点或槽位锚点布局。需要互相遮挡时按屏幕 Y 坐标排序，同深度使用稳定顺序，避免每秒刷新改变层级。
5. `ForegroundOccluders`：近处栅栏、门框、台沿、叶片或装饰，只遮住主体下缘等合理区域；交互热区仍覆盖完整可点区域，不被遮挡层吞掉。
6. `InteractionAndHUD`：标题、按钮、状态提示、计时、关闭入口；始终位于场景实体之上，留出明确安全区。

外景的远景、中景、前景可以使用低幅度视差，速度由远至近递增；建筑与可交互主体使用固定相机空间，不随背景漂移。室内禁止把整幅插画、玩法卡片和装饰压在同一个位图层：建筑壳体、功能设施、动态状态、前景遮挡和界面控件必须可独立替换与验收。

### 牛棚首个校准样例

- 画面主体：中央通道形成纵深消失方向，左右对称但有轻微生活化差异的牛栏；门口、侧墙与横梁延续外观的绿色桶拱屋顶和暖木材质。
- 固定层：屋顶内侧弧形梁架、墙面、窗、两侧围栏、中央通道、空饲槽。背景不得烘焙牛只或实时生产状态。
- 动态层：两头牛分别锚定左右栏位；牛只、状态徽标、乳杯进度与相应槽位编号绑定，点击牛只只选中对应牛栏。
- 前景层：近侧围栏或门槛可轻微覆盖牛只蹄部，不能遮住脸、生产状态和触摸主体；中央通道保持通透。
- 界面层：标题与关闭入口位于框架预留安全区；底部饲料、状态和收获控件属于操作层，不伪装成室内固定家具。

项目当前用一张 `3760 × 1359` 五格图集承载五个完整室内背景，运行时在背景上叠加动态填充层，再叠加标题和关闭控件。分层重绘时应先拆分图集母版，再按上面的图层顺序把固定设施、动态主体和前景遮挡分离；不得仅把节点排序当成已完成的美术分层。

## 4. 修改前工作卡

每次开始建筑美术或玩法联动任务，先填一张简短工作卡：

```text
建筑 ID / 显示名：
外观来源文件：
室内背景或图集裁片：
现有功能与状态：
要修复的不一致：
保持不变的玩法规则：
需要改动的资源 / 代码：
验收画面与操作：
```

在工作卡确认前，不扩写新的玩法规则，不批量生成整组建筑。缺失字段从项目现有配置、资源和代码读取；不得用猜测填入新机制。

## 5. 低成本迭代流程

1. **盘点**：查看当前建筑外观、室内图集、资源映射、运行时布局和现有玩法状态；记录每个建筑的外观标志与功能入口。
2. **定母版**：选一个代表性建筑，锁定屋顶弧度、墙面比例、描边、主色、入口、光照和接地方式；先出单张方案与室内对应关系。
3. **先校外观，再校室内**：外观轮廓通过后制作室内；室内背景保持相同的屋顶/墙体/材料识别点，并确保留给动态对象的空间与玩法槽位相符。
4. **再接玩法**：复用现有功能和状态，不改变无关机制；逐一核对可点击对象、生产状态、热区与画面中的实体是否一致。
5. **小批量扩展**：代表样例通过后再应用共同规范到相邻建筑；每批只处理一种明确差异，避免重做已验收的部分。
6. **验证交付**：在目标显示尺寸预览外观和室内；检查透明边缘、透视、屋顶曲率、图集裁切、资源路径、点击热区、状态更新及已有回归用例。记录修改文件、验证步骤和回退点。

## 6. 生成与图片编辑约束

- 先复用项目批准的建筑参考图，提示中分别写明“共享风格参数”和“本建筑独有结构”；不得只改变颜色来区分建筑。
- 同组多张新图先用等尺寸分格母图锁定轮廓、描边、光照与色板，再逐格裁切、校正和验收；母图不是运行时资源。
- 精修既有批准图时锁定未指定的轮廓、结构、配色和画布；禁止把局部修改扩展成整栋建筑重绘。
- 所有运行时 PNG 保持正确 RGBA 与既定画布比例；只允许等比缩放和整体平移，禁止把屋顶压扁或拉长以适配容器。
- 室内图集必须记录每个裁片的坐标和尺寸；背景不烘焙动物、产品、解锁状态或玩法文字。

## 7. 验收清单

- [ ] 牧场建筑的拱形屋顶属于同一曲率、檐口厚度和描边体系；轮廓不再出现互不相干的圆顶语言。
- [ ] 建筑仍能凭独有轮廓、材质和设施辨认用途，没有互相借用标志结构。
- [ ] 室内的屋顶内侧、墙面、门窗、材料和主色能够对应外观；入口与空间纵深关系成立。
- [ ] 室内动态实体、交互热区、状态提示和实际玩法槽位一一对应；背景没有重复烘焙动态状态。
- [ ] 远景、建筑壳体、固定设施、动态状态、前景遮挡和 HUD 可独立替换；重叠对象具有稳定的深度排序。
- [ ] 运行时显示比例、图集裁片、透明边缘、资源映射和已有玩法回归均通过验证。
- [ ] 交付记录包含修改清单、预览或测试结果，以及可恢复的原始资源 / 代码差异。

## 8. 当前盘点发现

- 建筑物品图标中，住宅与牛棚 / 仓库都采用弧形屋面，但弧线组织、檐口和屋面分片语言不完全一致；花房与恒温温室的玻璃拱顶亦需按“同曲率家族、不同功能结构”检查。
- 当前室内图集中，牛棚背景使用红色山墙与中央圆窗，而外观牛棚使用绿色桶拱屋顶与横向开放栏门；这组外观—室内识别差异应作为第一批校准对象。
- 当前五建筑室内图集为温室、牛棚、鸡舍、花房、蜂窝场景；住宅外观没有对应的住宅室内场景裁片。是否需要住宅室内玩法，应以现有玩法规划确认，不据此自动新增机制。
